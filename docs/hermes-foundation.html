Hermes et Foundation : comment ils travailleraient ensemble

Proposition. Hermes est la porte d'entrée à distance : il relaie et planifie, les briques pilotent leur travail, le Deuxième Cerveau garde la connaissance.

1CapturerUn message Telegram : Hermes le dépose dans 00 - Inbox. Le tri reste à toi.
2Lancer« lance planforge decompose » : Hermes exécute la commande de la brique et t'envoie le rapport.
3ValiderUne étape humaine (commit de l'analyse, fusion d'une Story semi-auto) : question sur Telegram, ta réponse, puis la commande suivante.
4PlanifierCron la nuit : agent epic <id>, compte rendu sur Telegram le matin.
5RetrouverHermes lit le vault pour te répondre ; sur ta demande, il dépose dans l'Inbox un compte rendu de Foundation.

Règles proposées

  • Hermes ne remplace aucune brique ; aucune brique ne le nomme.
  • Les briques n'écrivent pas dans le vault : seul Hermes y dépose, dans l'Inbox.
  • Les validations humaines restent ; aucune commande payante sans ton accord.
  • Écritures de mémoire et de skills de Hermes soumises à approbation.
  • docker.sock monté = root sur l'hôte : accès par VPN, authentification obligatoire.
  • Prérequis : les briques fonctionnelles sous Linux.
